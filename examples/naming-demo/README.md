# 整理命名示例

仅演示 `naming(context)` 协议，不是完整的智能重命名插件，不包含识别、批量文件操作或 MoviePilot 插件移植。

**兼容性：需要已接入 `naming` 能力与 `mv.render` 的 Muvyo 版本；这项主程序改动尚未发布，旧版不能安装使用。** 本目录是未签名的教学源码，不是可直接添加的插件仓库。

## 示例行为

- 没有音频编码时返回 `null`，沿用内置结果。
- 将音频编码的空白换成设置中的分隔符，用原模板调用 `mv.render(undefined, vars)`。
- 对渲染结果中的音频字段文本做 JavaScript 正则替换，将 `Atmos` 统一为 `ATMOS`，返回 `{ rendered }`。
- 例如 `TrueHD 7.1 Atmos` → `TrueHD.7.1.ATMOS`。后处理会替换路径中所有相同字段文本；真实插件若只想改字段，应在渲染前完成全部替换并返回 `{ vars }`。

## 接入

1. 复制本目录到自己的插件仓库 `src/<用户名>.naming`，将 manifest 的 `alice` 改为自己的作者命名空间。
2. 按仓库主文档签名、发布，管理员安装并启用插件。
3. 在「配置 → 识别 & 整理 → 重命名」添加命名方案，选择该插件，先批量预览，再保存。

一个方案只选择一个插件，每次处理一个文件。插件不拿到完整源路径或目标根目录，不执行文件操作；最终路径检查和实际整理由 Muvyo 负责。异常会停止当前文件，不自动回退。完整输入、返回格式与限制见 [命名能力协议](../../docs/naming.md)。
