# 安全机制

写给插件作者和想了解风险的 Muvyo 用户：插件在 Muvyo 里怎么运行、能碰到什么、碰不到什么。

## 运行在独立的受限进程里

- 每个插件在**独立的子进程**里运行，不在 Muvyo 主进程里。第一次调用时启动，闲置 2 分钟后自动退出。
- 进程分三层：监督进程、看守进程和执行插件代码的 QuickJS 解释器。看守进程与解释器以 **nobody** 身份运行，读不到 Muvyo 的配置、数据库和凭据。
- 解释器进程装有 **seccomp 系统调用白名单**：只能读写与主进程之间的管道、管理自己的内存，不能打开文件、不能联网、不能执行新代码。QuickJS 引擎本身即使有漏洞被利用，拿到的也只是这个没有权限的进程。
- 每次调用都在全新的 JS 环境里执行，有时长、内存和请求数上限，超时会被结束（见 [runtime.md](runtime.md#限制)）。

## 联网由 Muvyo 代办

- 插件自己不能联网，`mv.fetch` 的请求交给 Muvyo 主进程执行。
- 只允许访问 manifest 声明、且管理员安装时确认过的域名，以及用户填写的服务地址。
- Muvyo 先解析域名、确认是公网地址，再**连接到刚检查过的那个地址**（不会重新解析），每次跳转都重新检查，防止借跳转或改解析访问用户的内网。
- 用户填写的内网服务地址保存时固定解析出的地址；地址带路径时只能访问这段路径之下。服务地址不能是 Muvyo 自己的端口、Muvyo 已接入的服务，也不能是 FlareSolverr 这类能替插件访问任意网址的服务。
- 跳到别的网站时只带通用请求头，凭据与自定义头不跟过去；带正文的跳转不能跨网站。
- 插件不能申请网盘与 Muvyo 的域名，用户也不能把 Muvyo 已保存的凭据填进插件配置，防止插件借设置页骗取网盘账号。
- 每分钟联网次数与流量有上限，压缩响应解压后同样受大小上限约束。
- 插件给出的播放地址、图片地址同样经 Muvyo 按上述规则取回，**图片主机也必须在声明的域名里**。视频只转发媒体类型的响应；图片一律在服务端重新编码成 PNG 再交给浏览器，带脚本的 SVG、伪装成图片的网页都不会原样出现；这些响应都禁止浏览器猜类型和执行脚本。
- 声明域名时不接受 `*.github.io`、`*.workers.dev`、`*.co.uk` 这类公共后缀的通配，请写出具体的域名。

## 使用 Muvyo 的服务

- 插件在 `permissions.muvyo` 声明服务，由管理员安装 / 更新时确认后，才能请 Muvyo 用已配置的实例办事；新增服务需重新确认，不再声明的服务随更新收回。已下线的 `telegram.search` 旧声明直接忽略，不会获得授权。
- Muvyo 的账号、密码、Cookie、登录会话与实例标识留在主进程，**不进入沙箱**。插件只拿结果，不会拿到媒体文件路径、媒体库与条目编号、网盘文件编号、私有频道编号或消息地址。
- 服务在请求前后复核权限，并有用量、并发和时间限制。`mv.can` 只检查当前调用的授权，不保证实例可用；具体返回与失败处理见 [运行环境](runtime.md#使用-muvyo-的服务)。命名调用和「测试运行环境」不能使用服务。

### 读取 Telegram 频道

- 公开频道、公开超级群按用户名读；私有频道和群组只能读管理员勾选给这个插件的，用按插件区分的不透明 `ref` 指代，换一台 Muvyo 就变。勾选时 Muvyo 核对账号确实在这些会话里。
- 不给发送人，不开放私聊、联系人与成员列表。

### 用机器人搜索、给机器人发消息

- 只能用 `telegram_bots` 里声明、管理员确认过的机器人，或管理员在插件设置里添加的搜索机器人；对方必须是机器人账号，用户名对上真人、群或频道时直接拒绝。只读回这个机器人的回复，看不到其它聊天。
- 查询模板必须且只能有一个 `{keyword}`，只能是单条搜索命令，不能是启动、支付、解锁、签到等交互命令，也不能带链接；关键词不能是命令、深链或多行。
- 只点插件精确列出的按钮；带购买、解锁、加入、登录、积分、会员等字样的按钮在声明时就拒绝，运行时这类按钮和要密码的按钮一律不点。每次最多点 20 次、翻 5 页。
- 发出的查询结果不确定时不重发；同一机器人两次查询至少间隔 2 秒，Telegram 要求等待时整个账号暂停。
- `telegram.bot` 每个插件每天最多 30 条；消息内容由插件决定，确认安装窗口会提醒它可能触发兑换、转赠一类的操作。

### 推送资源给订阅

- 推送的条目按搜索结果同一套规则校验（链接白名单、文本清洗、条数上限），不合规的丢弃。
- 只交给勾选了这个插件、或没限定来源且插件「参与订阅与洗版」的订阅；片名命中后，过滤、去重、节流、文件身份校验与转存全按订阅规则。
- 同一插件、同一链接、同一标题只处理一次。排队期间插件被停用、收回推送授权或不再是订阅来源，整批撤销；转存结果不确定时不自动重提。
- 没命中订阅的资源默认丢弃。管理员打开「没命中订阅的资源也转存」后，按 TMDB 认作品、查媒体库，每条转存前再复核一次；「不识别，直接离线」按链接去重并记录到磁盘，重启后也不重复提交，结果不确定不重放。

### 其它

- 插件要用 FlareSolverr 时只能经 `mv.flaresolverr` 请 Muvyo 代发，插件连不到 FlareSolverr 本身，要打开的网页与最终停在的页面都必须在获准的域名里。
- 查询结果仍可能包含用户已有作品、频道正文、分享提取码和文件名；插件能把它们发给已获准访问的网站。管理员应核对服务与联网权限，作者不要把结果原样写入日志。

## 签名、更新与停用

- 安装与更新都只能从插件仓库进行，插件必须带有效的作者签名；证书过期后签的包装不上。
- 仓库里的每个文件都要与签名里的 SHA-256 一致，任何改动都会导致安装失败。
- **更新只认原作者**：已安装插件的新版本如果换了作者签名（按作者的数字账号标识，不看 GitHub 用户名），Muvyo 拒绝更新。命名空间也绑定作者的数字账号标识，GitHub 用户名被别人注册也拿不到。
- 更新时新增的访问域名会标出来，管理员确认后才生效；不能装回比已安装版本更旧的版本。
- 按安装包停用认的是签名内容本身（作者、插件 ID、版本、每个文件的哈希），改签名文件的排版绕不过去。
- 官方可以按插件、安装包、仓库、仓库签名公钥、作者或证书停用，最迟约 6 小时在所有设备上生效。

## 加密

- 插件代码默认用作者专属的密钥加密，仓库里只有密文；manifest 和 README 保持明文，安装前能看到权限。
- 解密密钥只发给有效授权的 Muvyo 安装，发放时不记录哪台设备领了哪位作者的密钥。
- 加密只能防止代码在仓库里公开，Muvyo 运行时终究要解开它，**不要在插件里放你自己的密钥或秘密**。
- 安装加密插件时，Muvyo 会提示「代码已加密，无法审阅」。

## 用户侧的默认保护

- 第三方插件需要有效的 Muvyo 授权才能运行；领取作者证书需要永久授权。
- 插件配置与 `mv.storage` 都加密保存；日志与报错里会把交给插件的配置值、插件数据打码，交给 AI 助手的只有固定的错误说明。
- 停用、更新、改设置或官方停用插件时，只结束插件这次操作，不影响订阅、机器人等调用它的功能继续运行。
- 被官方停用的插件立即停止运行，7 天后自动删除；期间官方撤销停用的，可照常使用。
- 新装的插件默认**不参与订阅与洗版**的自动搜索与转存，管理员在插件设置里打开「参与订阅与洗版」后才会参与；需要积分的资源默认不会自动换取链接，自动获取链接每天有次数上限（见 [capabilities.md](capabilities.md#resolve-token-)）。
- 刮削插件停用后，使用它的媒体库补全会失败，不会自动改用其它资料来源，避免资料来源被悄悄替换。
