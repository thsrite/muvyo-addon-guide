# Muvyo 事件示例

演示 `webhookEvent(e)` 协议：记录整理完成 / 失败、订阅完成、下载完成 / 失败事件，写进 Muvyo 日志，并在 `mv.storage` 里统计次数、保留最近几条。不联网，签名后就能装上试用。

**兼容性：需要支持 Muvyo 事件的版本。v3.9.14–v3.9.15 投递的是媒体服务器事件（`library.new`、`playback.stop` 等），已经下线；旧包里的这些声明会被忽略。**

## 试用

1. 复制本目录到自己的插件仓库 `src/<用户名>.eventlog`，把 manifest 的 `alice` 改成自己的作者命名空间，签名发布后在 Muvyo 安装。
2. 打开插件「设置」，打开 **接收 Muvyo 事件**（安装后默认关），保存后启用插件。不需要开「Webhook 推送」或「Webhook 接收」。
3. 手动整理一个文件，或等订阅、离线下载完成，到 Muvyo 日志里能看到 `[插件] 「示例事件记录」……` 的记录。

## 写真实插件时

- 想把事件推到别的网站（自己的通知服务、记账表格等），在 `permissions.domains` 声明那个网站，然后用 `mv.fetch` 推送。
- 投递在后台进行：插件慢不会拖住 Muvyo，但单次最多 30 秒，每个插件同时最多处理 2 个事件，再多的直接丢弃，不补发。`strm.generated` 在全量生成时逐个文件报，量很大，不需要就别声明。需要可靠同步时，在 `mv.storage` 里记下进度，配合定时任务补齐。
- 发新版时新增 `events`，更新后管理员要重新打开「接收 Muvyo 事件」，在更新说明里写清楚为什么要多收这些事件。

完整字段见 [能力与接口](../../docs/capabilities.md#webhook-事件)。
